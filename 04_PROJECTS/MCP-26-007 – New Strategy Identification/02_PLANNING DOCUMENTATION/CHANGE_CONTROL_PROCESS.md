# Change Control Process

## Change Triggers

- Proposed modification to regime definitions or thresholds
- Proposed change to entry, invalidation, or sizing logic
- Proposed relaxation of no-trade filters or risk constraints
- Proposed change to candidate evaluation criteria

## Process

1. Change request documented with rationale
2. Impact analysis completed (risk, scope, auditability, implementation implications)
3. Constraint check against doctrine and project scope
4. ML1 approval required before acceptance
5. Versioned update recorded in project artifacts

## Principle

No change is allowed that increases discretionary behavior, weakens risk controls, or reduces auditability.
