# Project Templates

**Location:** `04_PROJECTS/TEMPLATES.md`
**Status:** Draft — Requires ML1 Approval
**Applies to:** Project creation and delivery under `04_PROJECTS/**`

---

## 1. Purpose

This document defines the **canonical project documentation templates** used across the full project lifecycle.

Templates are:
- standardized starting points
- stage-specific
- non-authoritative until populated and approved

They exist to ensure:
- consistency across projects
- completeness appropriate to project stage
- shared expectations for delivery and control

---

## 2. Authority & Usage Rules

- ML1 retains sole authority for:
  - Go / No-Go decisions
  - baseline approval
  - steering decisions
  - formal project closure

- Templates:
  - do not imply approval
  - do not advance project stage
  - may be created or populated incrementally as a project matures

Agents may create or update templates **only when explicitly authorized** and within approved guardrails.

---

## 3. Lifecycle Stages & Required Templates

Projects follow four lifecycle stages.
Each stage has **defined documentation expectations**.

Documentation is classified as:
- **MANDATORY** — Required for stage completion
- **ELECTIVE** — Recommended but may be omitted based on project size/complexity

---

## 3.1 Initiation Stage

**Purpose:** Decide whether the project should exist.

### Core Documents

| Document | Classification | Purpose |
|----------|----------------|---------|
| **Project Charter** | MANDATORY | Scope, objectives, success criteria, authority, high-level risks |
| **Business Case / Rationale** | MANDATORY | Why this project, why now, expected value |
| **Stakeholder Register** | ELECTIVE | Who cares, influence level, decision rights |
| **High-Level Requirements Summary** | MANDATORY | What must be true for the project to be considered successful |
| **Initial Risk Register (Lite)** | MANDATORY | Obvious deal-killers and constraints |

### Outputs

- Go / No-Go decision
- Named project owner

---

## 3.2 Planning Stage

**Purpose:** Turn intent into an executable plan.

### Core Documents

| Document | Classification | Purpose |
|----------|----------------|---------|
| **Project Management Plan (PMP)** | ELECTIVE | Umbrella document referencing all plans below |
| **Scope Statement** | MANDATORY | In-scope, out-of-scope, assumptions, constraints |
| **Work Breakdown Structure (WBS)** | ELECTIVE | Decomposition of deliverables into work packages |
| **Schedule / Roadmap** | ELECTIVE | Milestones, dependencies, critical path |
| **Resource Plan** | ELECTIVE | People, roles, availability, constraints |
| **Budget / Cost Baseline** | ELECTIVE | Forecasted costs and burn rate |
| **Risk Register (Full)** | MANDATORY | Risks, likelihood, impact, mitigation |
| **Communications Plan** | ELECTIVE | Who gets what, when, and how |
| **RACI Matrix** | ELECTIVE | Responsibility clarity |
| **Change Control Process** | MANDATORY | How scope or requirements changes are handled |

### Outputs

- Approved baseline (scope, schedule, cost)

---

## 3.3 Execution + Monitoring & Control (Integrated)

**Purpose:** Do the work and ensure it stays inside guardrails.

Monitoring & Control runs **inside execution**, not as a separate phase.

### Core Documents

#### Delivery / Work Execution

| Document | Classification | Purpose |
|----------|----------------|---------|
| **Task Backlog / Sprint Board** | ELECTIVE | What is actively being worked on |
| **Assignment Briefs / Task Specifications** | ELECTIVE | Clear instructions for each work item |
| **Vendor / Dependency Tracker** | ELECTIVE | External dependency management (if applicable) |

#### Decision & Issue Handling

| Document | Classification | Purpose |
|----------|----------------|---------|
| **Decision Log** | MANDATORY | What was decided, by whom, and why |
| **Issue Log** | MANDATORY | Problems requiring resolution |
| **Change Requests Log** | MANDATORY | Proposed and approved changes |

#### Quality & Control

| Document | Classification | Purpose |
|----------|----------------|---------|
| **Quality Checklists** | ELECTIVE | Definition of "done" |
| **Risk Register (Updated)** | MANDATORY | New risks, retired risks |
| **Dependency & Blocker Log** | ELECTIVE | Cross-project and external blockers |

#### Monitoring & Performance

| Document | Classification | Purpose |
|----------|----------------|---------|
| **Status Report** | MANDATORY | Progress, risks, blockers, next steps |
| **KPI / Metrics Dashboard** | ELECTIVE | Schedule variance, cost variance, throughput |
| **Forecast / Re-baseline Analysis** | ELECTIVE | Course correction analysis (if needed) |

### Outputs

- Work products
- Updated logs (decisions, issues, risks, changes)
- Steering decisions
- Course corrections

---

## 3.4 Closure Stage

**Purpose:** Finish cleanly and preserve learning.

### Core Documents

| Document | Classification | Purpose |
|----------|----------------|---------|
| **Final Deliverables Acceptance Record** | MANDATORY | Formal sign-off on what was delivered |
| **Project Closure Report** | MANDATORY | What was delivered vs planned |
| **Lessons Learned / Retrospective** | MANDATORY | What worked, what didn't, why |
| **Post-Implementation Review** | ELECTIVE | Effectiveness assessment (if applicable) |
| **Final Budget Reconciliation** | ELECTIVE | Actual vs planned costs |
| **Archive Index** | MANDATORY | Where everything lives |

### Outputs

- Formal closure
- Knowledge retained for future projects

---

## 4. Summary: Mandatory Documents by Stage

| Stage | Mandatory Documents |
|-------|---------------------|
| **Initiation** | Project Charter, Business Case, Requirements Summary, Initial Risk Register |
| **Planning** | Scope Statement, Risk Register (Full), Change Control Process |
| **Execution** | Decision Log, Issue Log, Change Requests Log, Risk Register (Updated), Status Report |
| **Closure** | Deliverables Acceptance, Closure Report, Lessons Learned, Archive Index |

---

## 5. Template Granularity

Templates may exist as:
- standalone files, or
- structured sections within a larger document (e.g., PMP)

The choice of granularity depends on:
- project size
- risk profile
- stakeholder complexity

---

## 6. Change Control

Changes to this template set:
- affect all future projects
- may change delivery expectations

All changes require ML1 approval.
